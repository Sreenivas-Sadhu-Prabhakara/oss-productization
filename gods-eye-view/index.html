God's Eye View productization — a geospatial intelligence dashboard

God's Eye View is a browser 3D globe that plots live public spatial data — aircraft, ships, satellites, quakes, traffic — with keys brokered server-side. Productize it as a focused dashboard for one benign, paying vertical, using only feeds you're allowed to use commercially.

What it is

A photorealistic globe of live public data.

It renders a 3D globe in the browser and overlays live public spatial feeds — flights, vessels, satellites, earthquakes, traffic, even public cameras — with satellite imagery draped on terrain and a voice/NL query layer. A key design choice: a server-side key broker holds all the API keys and proxies feed and imagery calls, so no secrets sit in the client. That broker is both the architecture's strength and your cost centre.

The license reality

The code is MIT. The data is not.

MIT — but it covers the source only

The repository is MIT — fork, rebrand, close your wedge, run it as a service. But the license file explicitly appends a note that it covers the source code only, not the third-party data and imagery the app displays. So the code is free to build on; the feeds come with their own terms, and those are the real constraint (next section).

How you'd productize it

Pick one benign vertical and go deep.

The open project is a dazzling demo of everything. A product is a focused dashboard for one buyer with a budget. A strong, defensible default is disaster response / situational awareness:

  • Swap the feed set to ToS-clean sources relevant to the vertical (weather, seismic, maritime, aviation) and drop the rest.
  • Add a vertical dashboard — alerting, areas of interest, briefing views — on top of the globe.
  • Who pays: agencies, NGOs and operators who need a live common operating picture and can't stand up a geospatial stack themselves.

The groove

Pin-and-wedge, concretely.

  1. Pin at a release (here, v0.3.0); it's new and the hosted version is in flux.
  2. Self-host with the key broker intact — verify no keys reach the client bundle.
  3. Wire only ToS-clean feeds for your vertical, and cache/rate-limit to keep per-call costs sane.
  4. Build the vertical dashboard as your wedge, and write a per-feed data posture before you charge.

The catch

Feed terms, and the surveillance optics.

Every feed has its own ToS

ADS-B flights, AIS vessels, satellite elements, traffic, cameras, imagery (e.g. Sentinel-2 / Copernicus) — each carries its own license, redistribution and commercial-use terms. A feed that's free for a demo may forbid commercial redistribution entirely. A commercial product must use only ToS-clean sources, confirmed per feed.

Situational, not surveillance

The "spy satellite" framing and any person-level or public-camera data are a privacy and reputational liability in a commercial product. Disable person-level feeds and keep the product situational — tracking conditions and assets, not people.
