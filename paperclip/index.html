Paperclip productization — an AI agent operations layer

Paperclip is a self-hosted app for coordinating teams of AI agents toward business goals — budgets, org charts, work items. It's brand-new and bring-your-own-agent. Productize it internal-first: an operations layer over your own agent fleet, before anyone tries to sell it.

What it is

A coordination layer for agents you supply.

Paperclip lets you organise AI agents around goals, work items and budgets, with an org-chart mental model. It's bring-your-own-agent — it orchestrates agents you connect rather than shipping its own. The stack is a Node server + React UI + embedded PostgreSQL, with a quickstart CLI. It's very new, with a fast calendar-versioned release cadence, so expect its interfaces to move.

The license reality

MIT — the easy part.

MIT — full freedom

Fork, rebrand, close your wedge, run it as a service — all permitted. As with the other MIT projects here, the license is not the thing to plan around. The real questions are whether the category is ready and how you hold the credentials it needs.

How you'd productize it

Dogfood it before you sell it.

The honest path for a brand-new category is internal-first (M3 → SaaS only if it earns it):

  • Run it over your own agent fleet as an operations layer — what the agents are doing, what they're spending, what's stuck.
  • The wedge is governance + analytics: a usage, cost and audit layer over the orchestration — the part a team actually needs once more than one agent is doing real work.
  • Only then externalise: a paid product offered to others once you've proven it on yourself. No "zero-human company" claims — just useful agent ops.

The groove

Pin-and-wedge, concretely.

  1. Pin at a release (here, v2026.1117.0) and keep your integration a thin adapter — expect rework as it churns.
  2. Deploy the Node app + Postgres on a self-hosted PaaS; access-gate it.
  3. Wire one real agent and confirm it appears and can take work.
  4. Track activity + budget/spend, and cap it — this is the governance wedge and the safety rail at once.

The catch

Unproven category, concentrated credentials.

Build on ground that may shift

"Manage agents at work" is an emerging, unproven category — compelling as a demo, unsettled as a market. Don't build a business on it before you've proven value internally. Keep positioning honest; the hype framing is marketing, not reality.

And treat it as a security and cost-governance surface: it holds agent credentials and budget authority. Least-privilege access, encrypted secrets, and hard budget caps aren't optional when one misconfigured agent can spend real money.
